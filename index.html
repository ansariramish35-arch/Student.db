02 — Bonus · local AI assistant

Ask the database anything.

Built exactly as the brief specifies: backend code decides which queries are safe, fetches the rows, and hands them to the model as context — optionally via a local Ollama server running llama3.2:1b. Offline? A deterministic engine answers from the same records.

  • Counts — “how many students…”
  • Filters — “born after 2005”, “in Design”
  • Superlatives — oldest, youngest, latest enrollment
  • Lookups — find any student by name

Grounded, never raw SQL. Every answer ships with the exact grounded_records used to produce it, so responses are verifiable against the database.

POST /assistant/ask
grounded engine

Ask me anything about the student records. I answer only from rows fetched out of the database — never invented data.

Security, as briefed

  • · The model never executes SQL — backend code fetches records and injects them as JSON context.
  • · Dummy data only; .gitignore excludes students.db, env files and venvs.
  • · No secrets in source — all config via environment variables.
  • · Validation: 422 on bad input, 404 on missing records, 409 on duplicates.
